OpenGL Renderer V1

A from-scratch 3D rendering engine built in C++ and OpenGL as a personal learning project. It started as a way to understand the graphics pipeline at a low level, it's meant to keep evolving as I learn more.

Development Journey

The Idea

Most people learning graphics programming reach for a high-level library and start rendering triangles within an hour. I wanted the opposite — to slow down and actually understand what happens between "here's a mesh" and "here's a pixel on screen." OpenGL Renderer V1 began as that exercise: a from-scratch 3D rendering engine in C++ and OpenGL, built specifically to demystify the pipeline rather than abstract it away.

Core Architecture

The foundation wraps OpenGL's core objects — Vertex Array Objects (VAO), Vertex Buffer Objects (VBO), and Element Buffer Objects (EBO) — into clean, reusable C++ classes, alongside a dedicated ShaderClass for compiling and managing GLSL shader programs. A Camera class handles view and projection transforms, letting you move through the 3D scene interactively rather than staring at a static frame.

Custom Model Loader

One of the more interesting parts of the project is the model loader. Instead of reaching for Assimp — the standard, more powerful library most renderers use — I built my own loader using JSON for model data, as an exercise in understanding how model importing actually works under the hood. Parsing mesh and material data manually rather than treating it as a black box taught me far more about the process than a drop-in library ever would.

  • Custom JSON-based model format instead of relying on Assimp
  • Manual parsing of mesh and material data
  • Less capable than Assimp by design — the point was understanding, not completeness
  • Assimp integration is planned eventually for a more robust pipeline

Lighting & Rendering

The renderer implements basic lighting using dedicated vertex and fragment shader pairs (default/light) to demonstrate simple lighting models on textured meshes, with texture loading handled via stb_image. It's intentionally simple right now — the goal was getting the fundamentals correct before layering on complexity.

What's Next

This project reflects a hands-on, build-it-yourself approach to learning graphics programming — implementing core systems myself rather than jumping straight to high-level libraries. Since starting it, my understanding of OpenGL, C++, and 3D graphics fundamentals has grown significantly, and there's no fixed finish line in mind.

  • More advanced lighting models (PBR, multiple light types)
  • Switching the model loader over to Assimp for a more complete pipeline
  • Additional rendering features as they come up in learning
